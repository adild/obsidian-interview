## Eager Initialization

At the time the class is loaded instance is created. 

```
public class EagerInitializedSingleton {

    // The single instance of the class, created when the class is loaded.
    private static final EagerInitializedSingleton instance = new    EagerInitializedSingleton();

    // Private constructor to prevent external instantiation.
    private EagerInitializedSingleton() {
    }

    // Public static method to provide access to the single instance.
    public static EagerInitializedSingleton getInstance() {
        return instance;
    }
}
```
Key characteristics of Eager Initialization:
- **Instance creation at class loading:** The `instance` variable is initialized when the `EagerInitializedSingleton` class is loaded, not when `getInstance()` is first called.
- **Private constructor:** Ensures that the class cannot be instantiated directly from outside the class using the `new` keyword. This is crucial for enforcing the "single instance" rule of the Singleton pattern.
- Public static `getInstance()` method: This is the global access point to retrieve the single instance.
Advantages:
- **Simplicity:** It is straightforward to implement and understand.
- **Thread-safe by default:** Since the instance is created during class loading, there are no concurrency issues related to multiple threads trying to create the instance simultaneously.
Disadvantages:
- **Resource wastage:**
    The instance is created even if the application never actually uses it, which can lead to unnecessary resource consumption if the object is large or resource-intensive.

## Lazy Initialization

Same as Eager but creation of instance is done in **getInstance()** method.

Lazy initialization in the Singleton design pattern in Java refers to the practice of creating the singleton instance only when it is first requested, rather than at the time the class is loaded. This approach conserves resources by avoiding the creation of an object that might not be used.

```
public class LazySingleton {

    private static LazySingleton instance; // The single instance of the class

    // Private constructor to prevent external instantiation
    private LazySingleton() {
    }

    // Public static method to provide global access to the instance
    public static LazySingleton getInstance() {
        if (instance == null) { // Check if the instance has been created
            instance = new LazySingleton(); // Create the instance if it's null
        }
        return instance; // Return the existing instance
    }
}
```
- Public Static `getInstance()` Method:
    `public static LazySingleton getInstance()` provides the global access point to the singleton instance.
    - Inside this method, `if (instance == null)` checks if the instance has already been created.
    - If `instance` is `null` (meaning it's the first time `getInstance()` is called), `instance = new LazySingleton();` creates the single instance.
    - Subsequent calls to `getInstance()` will find `instance` already initialized and will directly return the existing instance.

Disadvantage (Thread Safety):
The basic lazy-initialized Singleton as shown above is not thread-safe. In a multi-threaded environment, if multiple threads concurrently call `getInstance()` when `instance` is `null`, they could all pass the `if (instance == null)` check and simultaneously create multiple instances, violating the Singleton principle. To address this, various thread-safe implementations exist, such as using `synchronized` methods, Double-Checked Locking, or the Bill Pugh Singleton implementation (Initialization-on-demand holder idiom).

## Synchronized method
Making the `getInstance()` method `synchronized` ensures that only one thread can execute it at a time. This prevents race conditions during instance creation.

```
    public class ThreadSafeSingleton {
        private static ThreadSafeSingleton instance;

        private ThreadSafeSingleton() {}

        public static synchronized ThreadSafeSingleton getInstance() {
            if (instance == null) {
                instance = new ThreadSafeSingleton();
            }
            return instance;
        }
    }
```
- **Cons:** Can lead to performance overhead as synchronization occurs on every call to `getInstance()`, even after the instance has been created.

## Double-Checked Locking

DCL aims to reduce the overhead of synchronization by only synchronizing the critical section where the instance is actually created. It involves checking for null twice, once outside and once inside the synchronized block. The `volatile` keyword is essential for `instance` to ensure visibility of writes across threads.

```
    public class DCLSingleton {
        private static volatile DCLSingleton instance;

        private DCLSingleton() {}

        public static DCLSingleton getInstance() {
            if (instance == null) {
                synchronized (DCLSingleton.class) {
                    if (instance == null) {
                        instance = new DCLSingleton();
                    }
                }
            }
            return instance;
        }
    }
```

problem: One thread will create an Object and will store it into cache but not in memory. Then another Thread will again create the Object since in memory Object is null. 
IMPORTANT point to remember: Above two cache are different for both the threads as both the threads were created on different cores.
To solve this, Volatile keyword is used.
volatile keyword is use to read/write object from memory instead of cache so if another thread tries to create new object it will go to memory as finds that it already has created.

## Bill Pugh
It uses a **static inner helper class** to hold the singleton instance. The inner class is not loaded into memory until the `getInstance()` method is called.

```
public class Singleton {

    // Private constructor to prevent instantiation
    private Singleton() {
    }

    // Static inner class - loaded only when getInstance() is called
    private static class Helper {
        private static final Singleton INSTANCE = new Singleton();
    }

    // Global access point
    public static Singleton getInstance() {
	    // Helper inner class is use to initialize the instance of outer class
        return Helper.INSTANCE;
    }
}
```

## Enum 

Constructors are always private 
One Object/instance is always created in Enum as per JVM
- **Guaranteed single instance** (by JVM)
- **Thread-safe** by default
- Protects against:
    - **Serialization issues** (automatically)
    - **Reflection attacks**
- **Simple and concise**

```
public enum Singleton {
    INSTANCE;

    // Example method
    public void doSomething() {
        System.out.println("Doing something...");
    }
}

```
